# Руководство по линтингу (ESLint)

Руководство по правилам линтера и работе с ESLint в проекте.

## Обзор

Проект использует ESLint для проверки качества кода с кастомными правилами для обеспечения консистентности и лучших практик.

## Запуск линтера

### Проверка кода

```bash
# Проверка всех файлов
npm run lint

# Автоматическое исправление
npm run lint:fix

# Проверка синхронизации переводов
npm run lint:translations
```

### В IDE

ESLint автоматически работает в большинстве IDE (VS Code, WebStorm, etc.) при установленном расширении ESLint.

## Основные правила

### 1. Правило `no-hardcoded-text`

**Цель:** Запретить использование hardcoded текстов в коде, требовать использование функции перевода `t()`.

**Почему это важно:**
- Поддержка мультиязычности (i18n)
- Легкое добавление новых языков
- Консистентность текстов в приложении
- Возможность запуска платформы на разных языках

**Что проверяется:**
- Hardcoded тексты в JSX элементах (`<div>Текст</div>`)
- Hardcoded тексты в JSX атрибутах (`placeholder="Введите текст"`)
- Hardcoded тексты в вызовах функций:
  - `setError('Текст ошибки')`
  - `toast.success('Успешно')`
  - `toast.error('Ошибка')`
  - `toast.info('Информация')`
  - `toast.warning('Предупреждение')`

**Правильное использование:**

```tsx
// ❌ Неправильно
<div>Добро пожаловать</div>
setError('Неверный код')
toast.success('Код отправлен')

// ✅ Правильно
<div>{t('welcome.message')}</div>
setError(t('errors.invalidCode'))
toast.success(t('sms.codeSent'))
```

**Исключения (автоматически игнорируются):**
- Пустые строки
- Только цифры и символы (`123`, `+389`, `2024`)
- URL (`https://example.com`, `mailto:test@example.com`)
- Символы-разделители (`:`, `|`, `•`, `/`, `×`)
- Одиночные заглавные буквы (`A`, `B`)
- Эмодзи

**Настройка правила:**

Правило настроено в `config/eslint.config.mjs`:

```javascript
'no-hardcoded-text/no-hardcoded-text': [
  'warn',
  {
    allowedElements: ['script', 'style', 'noscript', 'meta', 'link'],
    allowedAttributes: ['className', 'id', 'key', 'data-testid', 'data-cy', 'href', 'src'],
    translationFunction: 't',
    ignorePatterns: [
      '^\\s*$',           // Пустые строки
      '^[0-9\\s.,\\-+()]+$',  // Только цифры
      '^[a-z]+://',       // URL
      '^www\\.',          // www ссылки
      '^mailto:',         // Email ссылки
      '^#',               // Хештеги
      '^[:;|•\\-\\s\\/×·]+$',  // Разделители
    ],
  },
],
```

### 2. Правило `import/order`

**Цель:** Обеспечить консистентный порядок импортов.

**Правила:**
- Импорты группируются: `builtin` → `external` → `internal` → `parent` → `sibling` → `index`
- Между группами должна быть пустая строка
- Импорты сортируются по алфавиту внутри группы

**Пример:**

```typescript
// ✅ Правильно
import { useState } from 'react';
import { useRouter } from 'next/navigation';

import { useTranslation } from '@/hooks/useTranslation';
import { authApi } from '@/lib/api';

import { LoadingButton } from '@/ui';
```

### 3. TypeScript правила

- `@typescript-eslint/no-explicit-any`: `warn` - предупреждение при использовании `any`
- `@typescript-eslint/no-unused-vars`: `error` - ошибка при неиспользуемых переменных (игнорирует переменные, начинающиеся с `_`)

### 4. React правила

- `react-hooks/rules-of-hooks`: `error` - проверка правил хуков
- `react-hooks/exhaustive-deps`: `warn` - проверка зависимостей хуков
- `react/react-in-jsx-scope`: `off` - отключено (не нужно в React 17+)

### 5. Правила сложности и размера кода

- `max-lines`: `warn` - предупреждение при файлах >500 строк (исключая пустые строки и комментарии)
- `max-lines-per-function`: `warn` - предупреждение при функциях >150 строк
- `complexity`: `warn` - предупреждение при сложности функции >15

**Цель:** Предотвратить создание слишком больших файлов и функций, которые сложно поддерживать.

**Рекомендации:**
- Если файл превышает 300-400 строк, рассмотрите возможность разбиения на отдельные компоненты
- Если функция превышает 100 строк, вынесите логику в отдельные функции или хуки
- Если сложность функции высока, упростите логику или разбейте на более мелкие функции

## Работа с переводами

### Добавление новых ключей переводов

1. **Используйте ключ в коде:**
   ```tsx
   <button>{t('profile.changePhone.title')}</button>
   ```

2. **Добавьте ключ во ВСЕ файлы переводов:**
   - `locales/ro.json` (румынский)
   - `locales/ru.json` (русский)
   - `locales/en.json` (английский)
   - Любые другие языки в проекте

3. **Проверьте синхронизацию:**
   ```bash
   npm run lint:translations
   ```

### Структура ключей переводов

Используйте иерархическую структуру для организации:

```json
{
  "profile": {
    "changePhone": {
      "title": "Промена на телефон",
      "currentPhone": "Тековен телефон",
      "newPhone": "Нов телефонски број"
    }
  }
}
```

### Проверка синхронизации переводов

Команда `npm run lint:translations` проверяет:
- Все ключи присутствуют во всех языках
- Структура ключей идентична
- Нет лишних ключей в одном языке

## Частые ошибки и решения

### Ошибка: "Hardcoded text found in setError() call"

**Проблема:**
```tsx
setError('Неверный код')
```

**Решение:**
```tsx
setError(t('errors.invalidCode'))
```

### Ошибка: "Hardcoded text found in toast.success() call"

**Проблема:**
```tsx
toast.success('Код отправлен')
```

**Решение:**
```tsx
toast.success(t('sms.codeSent'))
```

### Ошибка: "Missing key in lib/locales/en.json"

**Проблема:** Ключ добавлен только в `ro.json`, но отсутствует в `en.json`.

**Решение:**
1. Добавьте ключ в `locales/en.json`
2. Запустите `npm run lint:translations` для проверки

### Ошибка: "Translation sync errors found"

**Проблема:** Ключи переводов не синхронизированы между языками.

**Решение:**
1. Проверьте вывод `npm run lint:translations`
2. Добавьте недостающие ключи во все языки
3. Удалите лишние ключи, если они не используются

## Автоматическое исправление

Некоторые проблемы можно исправить автоматически:

```bash
# Исправление форматирования и некоторых правил
npm run lint:fix

# Сортировка импортов
npm run sort-imports
```

**Примечание:** `no-hardcoded-text` правило не может быть исправлено автоматически, так как требует добавления ключей переводов вручную.

## Интеграция с CI/CD

Линтер запускается автоматически в CI/CD:
- При каждом push в репозиторий
- При создании pull request
- Проверяются все файлы `.ts` и `.tsx`

**Важно:** CI/CD не пропустит код с ошибками линтера.

## Лучшие практики

1. **Всегда используйте переводы** для пользовательских текстов
2. **Проверяйте линтер перед коммитом** - запускайте `npm run lint`
3. **Добавляйте ключи во все языки** одновременно
4. **Используйте осмысленные ключи** - `profile.changePhone.title` лучше, чем `text1`
5. **Группируйте ключи логически** - используйте иерархию (`profile.changePhone.*`)
6. **Проверяйте синхронизацию переводов** перед коммитом
