# Настройка видео для объявлений на продакшене

Краткое описание поведения фичи и технических требований к окружению см. в [Listings / Listing video](../features/listings.md). Здесь — пошагово: что сделать в AWS, какие переменные выставить на Render (или другом хостинге бекенда) и как проверить результат.

## Важно перед стартом

- **Скрыть секцию видео нельзя.** В форме объявления (`PhotosSection.tsx`) загрузчик видео рендерится всегда; ни `site.ts`, ни env-флаг его не отключают. Без настроенного MediaConvert пользователь загрузит клип и получит `errors.video.transcodingUnavailable`. Либо настройте транскодинг по этому гайду, либо добавляйте feature-flag в core отдельно.
- **Водяной знак на видео — отдельный PNG.** Фото-watermark (`assets/backend/watermark/logo.png`, ~200×200) для клипов **не подходит по размеру**. MediaConvert вставляет оверлей шириной **140 px** (`ImageInserter` в `mediaconvert.service.ts`). Загрузите отдельный PNG в бакет и укажите `LISTING_VIDEO_WATERMARK_S3_URI`.
- Рекомендуется задать **`AWS_MEDIACONVERT_SNS_TOPIC_ARN`**: без него вебхук принимает валидно подписанные SNS-сообщения из **любого** topic.

## 1. Что должно быть уже готово

- Рабочий бекенд NestJS с публичным **HTTPS** URL (например `https://api.example.com`).
- **PostgreSQL**: применены миграции PPCSL, включая колонку `listings.video` (JSONB).
- **S3** и ключи для загрузки медиа уже используются для фото — те же переменные `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION`, `AWS_S3_BUCKET_NAME` нужны и для видео (мультипарт-загрузка и импорт по URL).

Если фото в S3 не настроены, сначала приведите в порядок общий пайплайн загрузки файлов; без S3 видео недоступно.

## 2. Структура объектов в S3

Приложение использует префиксы:

| Префикс | Назначение |
|---------|------------|
| `video-input/{listingId}/{session}/source.*` | Временный исходник после multipart или после импорта по URL |
| `listings/{listingId}/video/` | Выходы MediaConvert (MP4 и кадр превью), затем преобразование превью в WebP |

Рекомендуется правило **S3 Lifecycle**: удалять объекты под `video-input/` через **1 сутки** (или по вашей политике), чтобы не копить недозагруженные или заброшенные сессии.

## 3. AWS Elemental MediaConvert

Сервис создаёт джобы программно (720p MP4 + кадр для превью). Нужны отдельные настройки в AWS.

### 3.1. Регион и endpoint

MediaConvert — **отдельный account-specific endpoint**, не обычный regional endpoint S3. В консоли AWS: **MediaConvert** → **Account** → скопируйте **API endpoint** для вашего региона.

В переменную окружения бекенда:

- **`AWS_MEDIACONVERT_ENDPOINT`** — значение endpoint из консоли (обязательно для включения транскодинга).

### 3.2. Очередь и IAM-роль для джобов

- **`AWS_MEDIACONVERT_QUEUE_ARN`** — ARN очереди MediaConvert (можно default queue).
- **`AWS_MEDIACONVERT_ROLE_ARN`** — IAM-роль, которую MediaConvert использует для чтения входа из S3 и записи выходов в бакет.

Роль должна позволять:

- читать объекты входного префикса и bucket (GetObject на источник);
- записывать выходы в `listings/*/video/` (PutObject и связанные операции по вашей политике).

Точный JSON политики зависит от имени бакета и префиксов; ориентируйтесь на официальный гайд AWS «Creating IAM roles for MediaConvert».

### 3.3. Учётные данные приложения

Клиент MediaConvert в коде использует те же **`AWS_ACCESS_KEY_ID`** и **`AWS_SECRET_ACCESS_KEY`**, что и S3. У IAM-пользователя (или роли выполнения приложения на Render) должны быть права как минимум на:

- `mediaconvert:CreateJob`, `mediaconvert:GetJob`, `mediaconvert:DescribeEndpoints` (если используете отдельные вызовы);
- доступ к S3 для вашего бакета в соответствии с тем, как устроены загрузки.

Если что-то из перечисленного для MediaConvert не задано или клиент не может авторизоваться, транскодинг считается выключенным: загрузка может завершиться ошибкой «transcoding unavailable».

## 4. Уведомления о завершении джобы (EventBridge → SNS → вебхук)

После `upload-complete` статус объявления становится `processing`. Обновление до `published` или `failed` приходит из AWS после успешного или неуспешного транскода.

Рекомендуемая цепочка:

1. **Amazon EventBridge**: правило с источником событий MediaConvert (например тип события уровня учётной записи для изменения состояния джобы).
2. Цель правила — **топик SNS**.
3. Подписка SNS типа **HTTPS** на URL бекенда:

   `https://<ваш-api-хост>/api/webhooks/mediaconvert`

Бекенд ожидает подпись SNS (`sns-validator`), для этого в приложении включён **raw body** для NestJS — не отключайте его и не подменяйте прокси так, чтобы ломался оригинальный JSON тела запроса.

Рекомендуется задать **`AWS_MEDIACONVERT_SNS_TOPIC_ARN`**: тогда вебхук принимает только сообщения из ожидаемого SNS topic и игнорирует валидно подписанные сообщения из других topic.

При первой подписке SNS пришлёт **`SubscriptionConfirmation`**; контроллер автоматически выполняет GET по `SubscribeURL` для подтверждения. Убедитесь, что процесс бекенда может делать исходящие HTTPS-запросы к AWS.

Альтернатива — настроить EventBridge API Destination напрямую на ваш HTTPS endpoint; тогда формат тела может отличаться от SNS и потребуется доработка кода (текущая реализация рассчитана на **SNS + Notification** с телом EventBridge внутри).

### Фоновая подстраховка

На сервере работает cron **каждые 5 минут**: зависшие записи в статусе `processing` старше ~20 минут перепроверяются через **MediaConvert GetJob**. Это не отменяет необходимость настройки доставки событий, но снижает риск «вечного processing» при сбое SNS.

## 5. Переменные окружения бекенда (чеклист)

Обязательные для работы видео вместе с уже существующими S3-переменными:

| Переменная | Описание |
|------------|----------|
| `AWS_REGION` | Регион бакета и MediaConvert |
| `AWS_S3_BUCKET_NAME` | Бакет медиа |
| `AWS_ACCESS_KEY_ID` | Ключ API |
| `AWS_SECRET_ACCESS_KEY` | Секрет ключа |
| `AWS_MEDIACONVERT_ENDPOINT` | Account endpoint из консоли MediaConvert |
| `AWS_MEDIACONVERT_QUEUE_ARN` | ARN очереди |
| `AWS_MEDIACONVERT_ROLE_ARN` | Роль выполнения джобы |
| `AWS_MEDIACONVERT_SNS_TOPIC_ARN` | ARN SNS topic для уведомлений MediaConvert; если задан, вебхук принимает только этот topic |

Опционально:

| Переменная | Описание |
|------------|----------|
| `AWS_CLOUDFRONT_URL` | Если медиа отдаётся через CloudFront — публичные URL для `webm`/`mp4`/превью строятся от этого базового URL |
| `VIDEO_MAX_SIZE_BYTES` | Переопределение лимита размера файла (байты); иначе значение по умолчанию из кода |
| `VIDEO_MAX_DURATION_SEC` | Переопределение максимальной длительности после транскода (секунды) |
| `LISTING_VIDEO_WATERMARK_S3_URI` | Полный `s3://bucket/key.png` или ключ относительно бакета к PNG-оверлею для WebM/MP4; без переменной логотип на видео не подставляется |

Импорт видео партнёрами (`POST /api/upload/video/from-url`) использует JWT и при необходимости заголовок **`x-import-secret`** — тот же секрет, что и для прочих импортов: **`KUPITO_IMPORT_SECRET`** (в старых конфигурациях встречается алиас **`CIPAUTO_IMPORT_SECRET`**).

## 6. Render.com и аналогичные PaaS

1. Добавьте все переменные из раздела 5 в **Environment** сервиса веб-API (бекенд).
2. Убедитесь, что сервис слушает тот порт и URL, которые вы указали в SNS subscription (`https://.../api/webhooks/mediaconvert`).
3. Исходящий трафик из Render обычно разрешён — это нужно для подтверждения подписки SNS и для вызовов AWS API.
4. После деплоя проверьте логи при первой успешной подписке SNS и при первой транскодированной ролике.

Если используете **несколько инстансов**, вебхук может попасть на любой инстанс — это нормально для stateless обработки SNS; главное — один и тот же код и доступ к БД.

## 7. Водяной знак (PNG в S3)

Фото-watermark платформы **не** подставляется в видео автоматически и обычно слишком крупный для оверлея. Нужен **отдельный** PNG под ширину **140 px**.

1. Подготовьте PNG с прозрачностью (разумный размер под оверлей ~140 px по ширине).
2. Загрузите объект в ваш медиа-бакет (например `branding/listing-video-watermark.png`).
3. Задайте **`LISTING_VIDEO_WATERMARK_S3_URI`** либо как `s3://имя-бакета/branding/listing-video-watermark.png`, либо как ключ `branding/listing-video-watermark.png` (тогда URI собирается с текущим `AWS_S3_BUCKET_NAME`).

MediaConvert должен иметь право читать этот объект из той же роли, что использует джоба.

## 8. Проверка после настройки

1. В форме редактирования объявления загрузите небольшой тестовый MP4 в допустимых лимитах.
2. Убедитесь, что после обработки в карточке/на странице объявления появляется видео и превью.
3. В S3 появляются файлы под `listings/<id>/video/`.
4. При ошибке транскода статус в данных объявления должен перейти в `failed`, а не зависнуть навсегда в `processing` (через вебхук или через reconcile cron).

## 9. Типичные проблемы

| Симптом | Что проверить |
|---------|----------------|
| «Транскодинг недоступен» | Заполнены ли `AWS_MEDIACONVERT_*`, жив ли endpoint, есть ли права у ключей |
| Долго `processing`, потом провал | Логи вебхука, подписка SNS, формат события (должен доходить SNS Notification к `/api/webhooks/mediaconvert`) |
| Видео без логотипа | Задан ли `LISTING_VIDEO_WATERMARK_S3_URI`, PNG в бакете, права роли MediaConvert на чтение |
| Публичные URL битые | `AWS_CLOUDFRONT_URL` или связка `AWS_S3_BUCKET_NAME` + `AWS_REGION` для виртуального хостинга S3 |

При изменении домена API пересоздайте HTTPS-подписку SNS на новый URL и дождитесь успешного подтверждения.
