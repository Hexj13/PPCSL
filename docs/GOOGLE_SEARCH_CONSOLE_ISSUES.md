# Проблемы в Google Search Console — Причины и Решения

**Дата:** 2025-12-17

Этот документ объясняет причины проблем, которые могут возникать в Google Search Console для домена `kupito.club`, и способы их решения.

---

## 1. Ошибка 403 для `cdn.kupito.club/`

### Причина проблемы

**Ошибка:** "Страница заблокирована из-за ошибки 403 (доступ запрещен)" для URL `https://cdn.kupito.club/`

**Корневая причина:**
- `cdn.kupito.club` — это CloudFront CDN, который обслуживает только статические файлы (изображения) из S3 bucket
- Файл `robots.txt` отсутствует в S3 bucket
- Когда Googlebot пытается получить доступ к `https://cdn.kupito.club/robots.txt`, CloudFront возвращает ошибку 403

### Почему это происходит

1. **CDN домены не предназначены для индексирования**
   - CDN (`cdn.kupito.club`) используется только для доставки статических ресурсов (изображения, CSS, JS)
   - Google не должен индексировать CDN домены
   - `robots.txt` должен быть только на основном домене (`kupito.club`)

2. **Отсутствие файла robots.txt в S3**
   - Если `cdn.kupito.club` был добавлен в Google Search Console, Googlebot пытается проверить `robots.txt`
   - Файл отсутствует в S3 bucket, поэтому CloudFront возвращает 403

### Решение

**Рекомендуемое решение:** Удалить `cdn.kupito.club` из Google Search Console

1. Перейти в Google Search Console
2. Удалить свойство `cdn.kupito.club` (если оно было добавлено)
3. Убедиться, что проверен только основной домен `kupito.club` (или `www.kupito.club`)
4. Проверить `robots.txt` на основном домене: `https://kupito.club/robots.txt`

**Альтернативное решение:** Загрузить `robots.txt` в S3 (если CDN домен должен остаться в Search Console)

```bash
cd backend
npm run upload-robots-txt
```

Затем инвалидировать кеш CloudFront для `/robots.txt` в AWS Console.

**Подробнее:** См. [CDN_ROBOTS_TXT_FIX.md](./CDN_ROBOTS_TXT_FIX.md)

## 2. Проблемы с переадресацией (Redirect Issues)

### Причина проблемы

**Ошибка:** "Страница с переадресацией" — Google обнаружил проблемы с редиректами для:
- `http://kupito.club/`
- `http://www.kupito.club/`
- `https://www.kupito.club/`

**Корневая причина:**
Googlebot видит несколько версий одного и того же URL и не может правильно определить каноническую версию из-за:
1. Неправильной последовательности редиректов
2. Цепочки редиректов (один URL перенаправляет на другой, который перенаправляет на третий)
3. Конфликтующих правил каноникализации
4. Временных редиректов (302) вместо постоянных (301)

### Почему это происходит

#### 2.1 Неправильная последовательность редиректов

В `frontend/middleware.ts` редиректы выполняются в следующем порядке:

1. **Удаление trailing slash** (строка 14-18)
2. **Удаление www.** (строка 20-30)
3. **HTTP → HTTPS** (строка 32-37)

**Проблема:** Если запрос приходит как `http://www.kupito.club/`, middleware может создать цепочку редиректов:
- `http://www.kupito.club/` → `http://kupito.club/` (удаление www)
- `http://kupito.club/` → `https://kupito.club/` (HTTP → HTTPS)

Это создает две цепочки редиректов вместо одного прямого редиректа.

#### 2.2 Отсутствие единой канонической версии

Google видит несколько версий одного URL:
- `http://kupito.club/`
- `https://kupito.club/`
- `http://www.kupito.club/`
- `https://www.kupito.club/`

Если все они не редиректятся на одну каноническую версию (`https://kupito.club/`), Google может пометить это как ошибку.

#### 2.3 Проблемы с определением протокола

В `middleware.ts` (строка 7-9) определение протокола зависит от заголовков:
```typescript
const protocol =
  request.headers.get('x-forwarded-proto') ||
  (request.nextUrl.protocol === 'https:' ? 'https' : 'http');
```

Если прокси-сервер (например, Cloudflare, Nginx) не передает заголовок `x-forwarded-proto` правильно, middleware может неправильно определить протокол.

#### 2.4 Конфликт с настройками хостинга

Если на уровне хостинга (Nginx, Apache, Cloudflare) также настроены редиректы, это может создать конфликт с редиректами в middleware Next.js.

### Решение

#### Шаг 1: Улучшить логику редиректов в middleware

Редиректы должны выполняться в правильном порядке и объединяться в один редирект:

```typescript
// Правильный порядок:
// 1. Сначала определить целевую каноническую версию (https://kupito.club)
// 2. Затем применить все изменения сразу
// 3. Выполнить один редирект 301
```

#### Шаг 2: Убедиться, что все версии редиректятся на каноническую

Каноническая версия: `https://kupito.club/` (без www, с HTTPS)

Все остальные версии должны редиректиться на нее:
- `http://kupito.club/` → `https://kupito.club/` (301)
- `http://www.kupito.club/` → `https://kupito.club/` (301)
- `https://www.kupito.club/` → `https://kupito.club/` (301)

#### Шаг 3: Проверить настройки хостинга

Убедиться, что на уровне хостинга (Nginx/Apache/Cloudflare) нет конфликтующих редиректов.

#### Шаг 4: Использовать только постоянные редиректы (301)

Все редиректы должны быть 301 (постоянные), а не 302 (временные).

## 3. Общие причины проблем в Google Search Console

### 3.1 Технические проблемы

1. **Ошибки сервера (4xx, 5xx)**
   - 403 (доступ запрещен) — неправильные права доступа
   - 404 (не найдено) — удаленные или перемещенные страницы
   - 500 (внутренняя ошибка сервера) — проблемы с кодом или базой данных

2. **Проблемы с robots.txt**
   - Файл недоступен (403, 404)
   - Неправильный синтаксис
   - Блокировка важных страниц

3. **Проблемы с sitemap.xml**
   - Sitemap содержит несуществующие URL (404)
   - Sitemap недоступен
   - Неправильный формат XML

### 3.2 Проблемы с индексированием

1. **Дублированный контент**
   - Несколько URL с одинаковым контентом
   - Отсутствие или неправильные canonical теги
   - Параметры URL создают дубликаты

2. **Проблемы с переадресацией**
   - Цепочки редиректов (более 3-4 редиректов)
   - Циклические редиректы
   - Временные редиректы (302) вместо постоянных (301)

3. **Мета-теги noindex**
   - Страницы с `noindex` случайно попали в sitemap
   - Конфликт между robots.txt и мета-тегами

### 3.3 Проблемы с контентом

1. **Тонкий контент**
   - Страницы с минимальным контентом
   - Страницы, требующие JavaScript для отображения контента

2. **Отсутствие структурированных данных**
   - Нет JSON-LD разметки
   - Неправильная разметка Schema.org

3. **Проблемы с производительностью**
   - Медленная загрузка страниц
   - Плохие Core Web Vitals

## 4. Рекомендации по предотвращению проблем

### 4.1 Регулярный мониторинг

1. **Еженедельная проверка Google Search Console**
   - Проверять раздел "Индексирование страниц"
   - Отслеживать новые ошибки
   - Проверять статус sitemap

2. **Мониторинг производительности**
   - Core Web Vitals
   - Скорость загрузки страниц
   - Мобильная версия сайта

### 4.2 Техническая SEO-гигиена

1. **Правильная настройка редиректов**
   - Все версии домена редиректятся на каноническую
   - Использование только 301 редиректов
   - Избежание цепочек редиректов

2. **Правильная настройка canonical**
   - Каждая индексируемая страница имеет canonical на себя
   - Нет глобального canonical на главную страницу

3. **Правильная настройка robots.txt и sitemap**
   - robots.txt доступен и корректен
   - sitemap содержит только существующие URL
   - Регулярное обновление sitemap

### 4.3 Тестирование перед деплоем

1. **Проверка редиректов**
   ```bash
   curl -I http://kupito.club/
   curl -I https://www.kupito.club/
   curl -I http://www.kupito.club/
   ```
   Все должны редиректиться на `https://kupito.club/` с кодом 301.

2. **Проверка robots.txt**
   ```bash
   curl https://kupito.club/robots.txt
   ```

3. **Проверка sitemap**
   ```bash
   curl https://kupito.club/sitemap.xml
   ```
