# SEO Audit & Indexing (Google Search)

**Date:** 2026-02-11
**Last updated:** 2026-02-11

This document audits technical SEO, crawlability, indexing, and Google Search visibility based on the current codebase.

---

## 1) Scope & Goals

### Goals

- Ensure **fast, reliable indexing** of the right pages.
- Prevent indexing of **private/thin/utility pages**.
- Avoid **duplicate content** via canonical, parameter handling, and redirects.
- Improve **SERP appearance** (titles, descriptions, structured data, OpenGraph).
- Reduce risk of **crawl traps** (infinite URL variations, unnecessary params).

### In scope

- Next.js App Router metadata/robots/sitemap
- Canonical strategy
- URL structure and parameter strategy
- Server rendering vs client-only rendering
- Structured data (JSON-LD)
- Internal linking
- Performance signals that impact SEO (CWV, heavy client JS)

### Out of scope (but recommended)

- Content strategy, backlinks, and PR (covered briefly as recommendations)

---

## 2) Current Implementation

### 2.1 Sitemap

**Location:** Backend `core/backend/src/sitemap/` (NestJS); frontend proxies via Next.js route handlers in `core/frontend/app/`.
**Format:** XML for sitemap index and child sitemaps; plain text for `/sitemap.txt`
**URL:** `/sitemap.xml` (sitemap index), `/sitemap.txt` (plain-text mirror); child sitemaps under `/sitemaps/*.xml`

The sitemap is generated by the backend from the database and served at `/api/sitemap.xml`, `/api/sitemap.txt`, and `/api/sitemaps/:name`. The frontend route handlers proxy `/sitemap.xml`, `/sitemap.txt`, and `/sitemaps/*` to the backend and return the correct response formats for crawlers.

- Sitemap **index** at `/sitemap.xml` lists child sitemaps.
- Child sitemaps: `pages.xml`, `brands-car.xml`, `brands-truck.xml`, `brands-moto.xml`, `tires.xml` (listed directly in the root index; no nested sitemap index), `sellers.xml`, `listings-YYYY-MM.xml`.
- `lastmod`, `changefreq`, `priority` where applicable; proper XML escaping (`&` → `&amp;`).
- 1-hour cache: Redis (backend) + `Cache-Control: public, max-age=3600, s-maxage=3600`.

**Included URLs:**
| Type | Included | File | Priority | Example |
|------|----------|------|----------|---------|
| Static pages | Yes | pages.xml | 0.2–1.0 | `/`, `/listings`, `/terms`, `/privacy`, `/faq`, `/contacts`, `/cookie-settings` |
| Brand pages | Yes | brands-*.xml | 0.8 | `/?brand=mercedes-benz` (bucket by `vehicleType`) |
| Brand+Model pages | Yes | brands-*.xml | 0.7 | `/?brand=mercedes-benz&model=c-class` |
| Seller boards | Yes | sellers.xml | 0.6 | `/board/{board_slug}` (active sellers with ≥1 active listing); `robots.txt` allows `/board/`; board pages are indexable |
| Individual listings | Yes | listings-YYYY-MM.xml | 0.9 | `/listings/:id` (Active only, by month) |
| Tire category / taxonomy | Yes | tires.xml | 0.7–0.8 | `/?category=tire`, `/?category=tire&tire_brand_ids=...`, `/?category=tire&tire_brand_ids=...&tire_model_ids=...` |
| Body type pages | No | — | — | Removed |
| Equipment filter pages | No | — | — | Not SEO-relevant |

### 2.5 Parameter Indexing Strategy

The homepage (`/`) uses an allowlist approach for indexable parameters. Current allowlisted groups include core search params (`brand`, `model`, `body_types`, `vehicleType`, `page`), tire params (`category`, `tire_*`), location params such as `cities`, and supported attribution params. See `INDEXABLE_SEARCH_PARAM_KEYS` in the code for the exact source of truth.

| Parameter group | Indexable     | Notes |
| --------------- | ------------- | ----- |
| `brand`, `model` | Yes          | Brand and brand+model landing pages |
| `body_types`, `vehicleType` | Yes | Vehicle taxonomy pages |
| `category`, `tire_*` | Yes      | Tire category and taxonomy pages |
| `cities` | Yes | Supported location filter |
| `page` | Yes (>1 only) | Pagination; page=1 canonicals to base URL |
| Non-allowlisted params | No | `noindex` + canonical to nearest clean URL |

### 2.6 URL Normalization (Proxy)

`core/frontend/config/proxy.ts` (Next.js 16 proxy convention) handles:

- Trailing slash removal (301)
- `www.` → apex redirect (301)
- HTTP → HTTPS redirect in production (301)

The proxy matcher excludes `robots.txt`, `sitemap.xml`, `sitemap.txt`, `sitemaps/`, and `site.webmanifest` so crawlers receive these resources without redirect logic.

### 2.7 Listing Detail Page (`/listings/[id]`)

- **SSR:** Full server-side rendering with `generateMetadata` and JSON-LD
- **Metadata:** Dynamic title, description, keywords (with `.filter(Boolean)`), canonical, OG image
- **OG Image fallback:** If no listing image, uses `${siteUrl}/og-image.jpg` (absolute URL)
- **Auto-close:** Listings auto-close after 90 days, keeping indexed pages fresh
- **Closed listings:** Pages for listings with status `Closed` return `noindex` in metadata (while remaining crawlable), so closed offers gradually disappear from Google Search
- **404 handling:** `notFound()` for missing listings with `noindex`

## 3) Resolved Issues (History)

### P0 — Private/utility pages were indexable (RESOLVED)

All private routes now have `robots: { index: false }` in metadata AND are blocked in `robots.txt`.

### P0 — Canonical strategy was wrong (RESOLVED)

Global canonical removed from root layout. Each indexable route sets canonical to itself.

### P0 — Listing detail was client-only (RESOLVED)

Converted to SSR with `generateMetadata` and server-rendered JSON-LD.

### P0 — Structured data was injected via useEffect (RESOLVED)

JSON-LD is now rendered in SSR output.

### P1 — Vehicle listing schema stopped using generic `Product` (RESOLVED 2026-02-11)

Vehicle listing detail pages switched from `Product` to `Vehicle`. This eliminated the Search Console warnings that were caused by treating vehicle listings as generic products:

- `aggregateRating` (missing)
- `hasMerchantReturnPolicy` (missing)
- `shippingDetails` (missing)

Vehicle listings now use a more appropriate schema type, while tire listings continue to use `Product`.

### P1 — Sitemap was text format / not accepted by Search Console (RESOLVED 2026-02-11)

Sitemap is now generated by the backend (NestJS) and served as XML. Frontend route handlers proxy `/sitemap.xml` and `/sitemaps/*` to the backend API. This provides:

- Correct `Content-Type: application/xml; charset=utf-8`
- Proper XML escaping (`&` → `&amp;`)
  - Sitemap index + child sitemaps (pages, brands, tires, sellers, listings by month)
- 1-hour Redis cache and Cache-Control headers
- Individual listings and seller boards included

### P1 — Body type combinations bloated sitemap (RESOLVED 2026-02-11)

Removed bitwise combination generation (~157 URLs) in favor of single body type entries (~22 URLs).

### P1 — Layout duplicated metadata fetch for listings (RESOLVED 2026-02-11)

`listings/[id]/layout.tsx` was making a separate API fetch to generate the same metadata as `page.tsx`. Layout simplified to a pass-through wrapper.

### P1 — `/complete-profile` missing from robots.txt (RESOLVED 2026-02-11)

Added to disallow list.

## 4) Recommended Improvements (Medium Priority)

### P2 — Create SEO landing pages as real routes

Query URLs can rank, but **path-based** pages are easier to scale and control.

Examples:

- `/brands/toyota`
- `/brands/toyota/yaris`

**Benefits:**

- Cleaner URL hierarchy
- Easier canonical and internal linking
- Easier to build unique content blocks (FAQs, descriptions)

### P2 — Internal linking strategy

Add visible HTML links to:

- Top brands and top brand+model combinations
- Cities and categories (if relevant)

**Rule:** only link to pages you want indexed.

### P2 — Expand structured data on collection pages

For listing result pages, `ItemList` schema is already implemented with the first N items.
Consider adding `CollectionPage` for body type landing pages.
