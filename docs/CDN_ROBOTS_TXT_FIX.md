# Fix: robots.txt 403 Error on cdn.kupito.club

## Quick Fix

**Fastest solution:** Upload `robots.txt` to S3 using the script:

```bash
cd backend
npm run upload-robots-txt
```

Then invalidate CloudFront cache for `/robots.txt` in AWS Console. The error should disappear within a few minutes.

---

## Problem

Google Search Console shows error 403 when trying to access `https://cdn.kupito.club/robots.txt`:
- **Error:** "Failed to send a request for re-scanning"
- **Reason:** "Page blocked due to error 403 (access forbidden)"

## Root Cause

`cdn.kupito.club` is a CloudFront CDN that serves static files (images) from S3 bucket. The `robots.txt` file doesn't exist in the S3 bucket, so CloudFront returns 403 when Googlebot tries to access it.

## Solutions

### Solution 1: Remove CDN Domain from Google Search Console (Recommended)

**Why:** CDN domains (`cdn.kupito.club`) are for serving static assets, not for indexing. Google should only check `robots.txt` on the main domain (`kupito.club`).

**Steps:**
1. Go to Google Search Console
2. Remove `cdn.kupito.club` from the property list (if it was added)
3. Ensure only `kupito.club` (or `www.kupito.club`) is verified
4. Check `robots.txt` on the main domain: `https://kupito.club/robots.txt`

**Note:** The main domain already has `robots.txt` generated by Next.js at `frontend/app/robots.ts`.

### Solution 2: Upload robots.txt to S3 (Recommended Fix)

To fix the 403 error, upload `robots.txt` to your S3 bucket. This will make it accessible via CloudFront CDN.

**Option A: Using Script (Recommended)**

1. **Run the upload script:**
   ```bash
   cd backend
   npm run upload-robots-txt
   ```

   The script will:
   - Create a simple `robots.txt` that allows all crawlers
   - Upload it to your S3 bucket
   - Show you the URLs where it's accessible

2. **Invalidate CloudFront cache (if needed):**
   - Go to AWS Console → CloudFront → Your distribution
   - Create invalidation for `/robots.txt`
   - Wait for invalidation to complete (usually 1-2 minutes)

3. **Verify:**
   ```bash
   curl https://cdn.kupito.club/robots.txt
   ```
   Should return 200 OK with robots.txt content

**Option B: Manual Upload via AWS Console**

1. **Create robots.txt file:**
   ```txt
   User-agent: *
   Allow: /
   ```

2. **Upload to S3 bucket:**
   - Go to AWS Console → S3 → Your bucket (`kupito-uploads`)
   - Click "Upload"
   - Select the `robots.txt` file
   - Under "Permissions", ensure "Read" is allowed for "Everyone (public access)"
   - Upload

3. **Verify CloudFront access:**
   - CloudFront should automatically serve the file
   - Test: `curl https://cdn.kupito.club/robots.txt`
   - Should return 200 OK with robots.txt content

4. **Update CloudFront cache (if needed):**
   - Go to CloudFront distribution
   - Create invalidation for `/robots.txt`
   - Wait for invalidation to complete

### Solution 3: Configure CloudFront Custom Error Response (Advanced)

If you want to redirect robots.txt requests to the main domain:

1. Go to CloudFront distribution → Error Pages
2. Create custom error response:
   - HTTP Error Code: `403`
   - Path Pattern: `/robots.txt`
   - Response Page Path: (redirect to main domain)
   - HTTP Response Code: `301` or `302`

**Note:** This is more complex and may not be necessary if Solution 1 is implemented.

## Recommended Action

**Use Solution 1** - Remove `cdn.kupito.club` from Google Search Console. The CDN domain is only for serving static assets (images), and Google should index and check robots.txt on the main domain (`kupito.club`) only.

## Verification

After implementing Solution 1:
1. Verify `https://kupito.club/robots.txt` is accessible (should return 200)
2. In Google Search Console, check robots.txt for `kupito.club` (not `cdn.kupito.club`)
3. The error should disappear from Search Console
