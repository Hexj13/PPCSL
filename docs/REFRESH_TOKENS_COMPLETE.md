# Refresh Tokens - Полная документация

## Обзор

Система refresh токенов реализована для безопасного обновления JWT access токенов без необходимости повторного логина.

## Архитектура

### Токены

- **Access Token (JWT)**: Срок жизни 1 час, используется для аутентификации запросов
- **Refresh Token**: Срок жизни 7 дней, используется для получения новых access токенов

### Безопасность

- Refresh токены хранятся в базе данных
- При использовании refresh токена, старый токен отзывается (revoked)
- Генерируется новый refresh токен (token rotation)
- Истекшие токены автоматически удаляются ежедневно в 2:00 AM

## Backend Implementation

### Entity и миграция

- Создана таблица `refresh_tokens` с индексами
- Миграция: `1762642930000-CreateRefreshTokensTable.ts`

### RefreshTokenService

- Генерация токенов (128 символов, 7 дней)
- Валидация токенов
- Отзыв токенов
- Автоматическая очистка истекших токенов (cron job в 2:00 AM)

### AuthService

- Метод `login()` возвращает `refresh_token`
- Новый метод `refreshTokens()` для обновления токенов
- Token rotation (старый токен отзывается)
- Отзыв всех токенов при удалении аккаунта

### API эндпоинт

- `POST /api/auth/refresh` - обновление токенов
- Rate limiting: 10 запросов в минуту
- Swagger документация

## Как это работает

### Поток аутентификации:

1. **Логин**:
   ```
   POST /api/auth/login
   → Возвращает: { access_token, refresh_token, user }
   → Сохраняется в localStorage и store
   ```

2. **Использование access token**:
   ```
   Запрос с Authorization: Bearer {access_token}
   → Если валиден: успешный ответ
   → Если истек (401): автоматическое обновление
   ```

3. **Автоматическое обновление**:
   ```
   401 ошибка
   → Проверка refresh_token в localStorage
   → POST /api/auth/refresh с refresh_token
   → Получение новых токенов
   → Повтор оригинального запроса
   → Сохранение новых токенов
   ```

4. **Истечение refresh token**:
   ```
   Refresh token истек или невалиден
   → Удаление всех токенов
   → Редирект на /login
   ```
