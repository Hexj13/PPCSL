# Настройка SMTP (локально и прод)

**English:** [smtp-email-setup.md](./smtp-email-setup.md)

Как включить **транзакционную почту** (подтверждение email, смена адреса, уведомления о безопасности) в бэкенде NestJS. Отправка реализована через Nodemailer в `core/backend/src/auth/infrastructure/services/email.service.ts`, а HTML писем генерируется из MJML-блоков в `core/backend/src/common/email/email-template.ts`.

## Поведение

- Письма о безопасности и прочая транзакционная почта (кроме подтверждения адреса) уходят только на **подтверждённый** email (`emailVerified`). Исключение — письма подтверждения регистрации и смены email: их намеренно отправляют на ожидающий подтверждения адрес.
- Если заданы **все четыре** переменные `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER` и `SMTP_PASSWORD`, приложение создаёт SMTP-транспорт и отправляет письма.
- Если чего-то не хватает, **транспорт не создаётся**; `sendMail` ничего не делает. Запросы к API **не падают** только из‑за отсутствия SMTP.
- Ссылки в письмах строятся от **`FRONTEND_URL`**. Если не задано, бэкенд подставляет `http://localhost:3000`.
- Макеты писем рендерятся из MJML на этапе отправки; для лучшей кросс-клиентной совместимости не используйте внешние webfont-шрифты.
- **`SMTP_FROM`** необязателен. Значение по умолчанию в коде: `noreply@kupito.club`. У провайдера может быть требование, чтобы `From` совпадал с разрешённым отправителем или доменом.
- `replyTo` заполняется из `SUPPORT_EMAIL` (по умолчанию `support@kupito.club`).
- В `NODE_ENV=production` бэкенд валидирует email-конфиг при старте:
  - `FRONTEND_URL` обязателен и должен быть абсолютным `http(s)` URL
  - `FRONTEND_URL` не должен указывать на localhost и не должен содержать path
  - частичная настройка SMTP отклоняется (`SMTP_*` должны быть либо полностью заданы, либо полностью отсутствовать)

| Переменная      | Обязательно | Назначение |
|-----------------|-------------|------------|
| `SMTP_HOST`     | Да*         | Хост SMTP-сервера |
| `SMTP_PORT`     | Да*         | Порт (см. ниже) |
| `SMTP_USER`     | Да*         | Логин SMTP (часто полный email) |
| `SMTP_PASSWORD` | Да*         | Пароль или пароль приложения |
| `SMTP_FROM`     | Нет         | Заголовок `From` (например `Kupito <noreply@yourdomain.com>`) |
| `SUPPORT_EMAIL` | Нет         | `Reply-To` и контакт поддержки в футере письма |
| `FRONTEND_URL`  | Нет         | Базовый URL для ссылок в письмах |
| `EMAIL_VERIFICATION_TOKEN_EXPIRES_IN` | Нет | Срок жизни JWT для ссылок подтверждения регистрации и смены email (строка для `jsonwebtoken`, например `72h`). По умолчанию: `72h`. Для локальной проверки экрана «ссылка истекла» можно поставить, например, `5s` (после изменения перезапустить API). |

\*Обязательны только если нужна реальная отправка почты.

**Порт и TLS:** В коде `secure: true` включается только для порта **465**. Для **587** Nodemailer обычно использует STARTTLS. Берите порт из документации вашего провайдера.

## Локальная разработка

1. Откройте файл окружения бэкенда (в платформенном репозитории с submodule: `core/backend/.env`; отдельный клон PPCSL: `backend/.env`).
2. Укажите `FRONTEND_URL` на локальный фронт (обычно `http://localhost:3000`).
3. Добавьте переменные SMTP (см. раздел Google Workspace ниже или тестовый ящик).

**Проверка без доставки в реальный ящик:** используйте сервис перехвата SMTP (например Mailtrap) и подставьте его host, port, user и password в четыре переменные `SMTP_*`.

**Предпросмотр всех шаблонов писем (только dev/stage/test):** из каталога `core/backend`, при настроенном Mailtrap (или любом SMTP):

```bash
SEND_TEST_EMAIL_TO="<адрес из Mailtrap inbox>" npm run send-test-emails
```

Опционально: `SEND_TEST_EMAIL_LOCALE=en|ro|ru` (если не задано — `en`). Тексты берутся из `locales/backend/*.json`, секция `emails`.

Отправляется семь тестовых писем (верификация, смена email, уведомления о пароле/телефоне/email, напоминание об обновлении объявлений, недельный отчёт просмотров). Скрипт не запускается при `NODE_ENV=production`. Между отправками есть пауза; при ошибке SMTP выполняется несколько повторов с увеличивающейся задержкой (удобно при лимитах Mailtrap).

Если меняете разметку/стили шаблонов, редактируйте `core/backend/src/common/email/email-template.ts` и снова запускайте `npm run send-test-emails`, чтобы проверить итоговый рендер в реальном inbox.

**Без SMTP:** приложение работает; сценарии, которые шлют письма, просто ничего не доставят.

## Прод (Render.com)

1. В панели Render откройте **backend** web service (сервис с Nest API).
2. Раздел **Environment** — добавьте те же переменные, что в таблице. Пароли (`SMTP_PASSWORD` и т.п.) помечайте как **Secret**, если Render это предлагает.
3. `FRONTEND_URL` должен быть **публичным** URL сайта (например `https://your-domain.com`), как его открывают пользователи — иначе ссылки в письмах ведут не туда.
4. Выполните повторный деплой (**redeploy**) или перезапуск сервиса, чтобы подтянулись новые переменные.

Исходящие IP у Render часто **динамические**, если нет опции со статическим egress. Если Google **SMTP relay** настроен **только по IP**, связка с Render ненадёжна; лучше аутентифицированный SMTP через учётную запись Workspace (ниже).

## Google Workspace (корпоративная почта Google)

Для Render и локалки разумный вариант: отдельный **почтовый ящик** в вашем домене (например `noreply@yourcompany.com`) и **отправка через SMTP** на серверы Google.

### Типовые шаги

1. Создайте или выберите пользователя Workspace только для рассылки (например `noreply@...`).
2. Включите **двухэтапную аутентификацию** для этого пользователя (для паролей приложений это обычно обязательно; в Workspace политику задаёт админ).
3. В аккаунте Google этого пользователя создайте **пароль приложения** (Безопасность → Пароли приложений) и укажите его в `SMTP_PASSWORD`. Если пароли приложений отключены для организации, нужен админ Workspace или другой поддерживаемый способ аутентификации.
4. Настройте бэкенд:

   ```env
   SMTP_HOST=smtp.gmail.com
   SMTP_PORT=587
   SMTP_USER=noreply@yourcompany.com
   SMTP_PASSWORD=<16-символьный-пароль-приложения>
   SMTP_FROM=Kupito <noreply@yourcompany.com>
   FRONTEND_URL=https://your-production-domain.com
   ```

5. Убедитесь, что **`SMTP_FROM`** допустим для Google (часто тот же адрес, что `SMTP_USER`, или алиас, настроенный в Gmail / Admin).

### SMTP relay (`smtp-relay.gmail.com`)

Иногда используют [службу SMTP relay Google](https://support.google.com/a/answer/2956491) вместо `smtp.gmail.com`. Настройки зависят от правил в Admin Console (диапазоны IP, аутентификация, TLS). Если relay **только по IP**, а IP Render не фиксированы, доставка может не работать или работать нестабильно. Согласуйте с администратором Google Workspace.

### Доставляемость

На проде для домена желательно настроить **SPF** и **DKIM** (и при необходимости **DMARC**) в соответствии с тем, как вы отправляете почту. Админы Workspace делают это в Google Admin и в DNS. При плохой настройке DNS письма могут уходить в спам даже при верных учётных данных SMTP.

## Устранение неполадок

| Симптом | Что проверить |
|---------|----------------|
| Писем нет, API без ошибки | Не все переменные SMTP заданы → транспорт не создаётся. |
| API отвечает 400 с ошибкой SMTP | Логин/пароль, хост/порт, блокировка со стороны провайдера (логи Render). |
| Ссылки открывают не тот хост | Задайте `FRONTEND_URL` как реальный публичный URL фронта. |
| Google: «неверные учётные данные» | Пароль приложения vs обычный пароль; 2FA; политика органа, запрещающая SMTP или пароли приложений. |
